=head1 NAME

Alien::Xrepo::Base - Base class for Alien distributions using Xrepo

=head1 SYNOPSIS

Subclass C<Alien::Xrepo::Base>, declare which xrepo package(s) the module represents with L</"C<pkg_name( )>">, and
optionally steer the install with L</"C<install_opts( )>">. During C<./Build>, the Builder installs those packages with
xrepo, shallow-copies the finished artifacts into the module's share directory, and records the result in a generated
C<::ConfigData> so the accessors below resolve without re-running the resolver.

In your subclass C<lib/Alien/Zstd.pm>:

    package Alien::Zstd;
    use v5.40;
    use experimental 'class';
    use Alien::Xrepo::Base;

    class Alien::Zstd : isa(Alien::Xrepo::Base) {
        method pkg_name { 'zstd' }

        # Optional: customize installation
        method install_opts {
            return (
                kind    => 'shared',
                configs => { legacy => 1 }
            );
        }
    }

    1;

A multi-package family (such as SDL3) returns a list of package names and may ship a tree of patched recipes:

    package Alien::SDL3;
    use v5.40;
    use feature 'class';
    use Alien::Xrepo::Base;
    use Path::Tiny qw[path];

    class Alien::SDL3 : isa(Alien::Xrepo::Base) {
        method pkg_name { [ 'libsdl3', 'libsdl3_image', 'libsdl3_ttf' ] }

        method install_opts {
            return (
                kind        => 'shared',
                local_repos => [ path(__FILE__)->parent->parent->parent->child('recipes') ],
            );
        }
    }

    1;

When the packages differ in version, installer flags, or recipe options, give each one its own hashref instead of one
global L</"C<install_opts( )>">. This is how you build a shared library alongside a binary tool in one module:

    package Alien::MediaKit;
    use v5.40;
    use experimental 'class';
    use Alien::Xrepo::Base;

    class Alien::MediaKit : isa(Alien::Xrepo::Base) {
        method pkg_name {
            return [
                'zstd',
                { name => 'libsdl3', version => '3.4.12', kind => 'shared', configs => { wayland => 1 } },
                { name => 'ninja',   kind => 'binary' },
            ];
        }

        # Global options apply to every package; per-package entries override
        # them per-key (and recipe configs merge: per-package ones win).
        method install_opts {
            return ( configs => { zlib => 1 } );
        }
    }

    1;

In your C<Build.PL>:

    use lib 'lib';
    use Alien::Xrepo::Base;

    # Pass your subclass name to the builder
    Build_PL('Alien::Zstd');

=head1 DESCRIPTION

C<Alien::Xrepo::Base> is a base class designed to simplify the creation of C<Alien::*> distributions that use C<xrepo>
to manage native dependencies. The heavy lifting is done by L<Alien::Xrepo>, which shells out to xrepo via
L<Alien::Xmake>; this class wires a concrete Alien front-end onto it.

It leverages Perl 5.40's native C<class> features and provides a C<Module::Build::Tiny>-compatible build system that:

=over

=item 1. Installs the requested package via C<xrepo> into a C<share> directory during the build phase.

=item 2. Captures all relevant metadata (include dirs, lib dirs, flags, etc.).

=item 3. Generates a C<ConfigData.pm> module for runtime access.

=item 4. Handles portable path resolution both from C<blib> (during development/testing) and from the final installation directory.

=back

=head1 CONSTRUCTOR

=head2 C<new( ... )>

    my $alien = Alien::Zstd->new(
        pkg_name           => 'zstd',
        version_constraint => 'latest',
        root               => '/path/to/project-root',
        verbose            => 1
    );

Creates a new instance. If C<pkg_name> is omitted it is inherited from the subclass C<pkg_name> method.

=over

=item B<pkg_name>

The name of the package as it appears in the C<xrepo> repository (e.g., C<zstd>). If omitted, the value returned by the
subclass C<pkg_name> method is used. One of the two must be provided. May also be an array reference (or list) of
package names to install and expose C<SDL3>-style families of related libraries (see the C<Alien-SDL3> example in
C<eg/examples/>). Each entry may be a plain name or a hashref of per-package options (version, installer flags, recipe
configs) as described under L</"C<pkg_name( )>">. The first name is the C<primary> package used when no package is
selected.

=item B<version_constraint>

Optional semantic version constraint (e.g., C<1.6.x>, C<latest>, C<1.6.32>). Passed to C<Alien::Xrepo::install> and
appended to the C<xrepo> install spec. A per-package C<version> (see L</"C<pkg_name( )>">) overrides this for that
package.

=item B<root>

Optional path to an isolated, local installation root for packages and configuration. When set, C<XMAKE_CONFIGDIR> and
C<XMAKE_PKG_INSTALLDIR> point inside this directory so the package does not touch the global C<~/.xmake> environment.

=item B<verbose>

Boolean. If true, prints xrepo status output to C<STDOUT>. Defaults to C<0>.

=back

=head1 SUBCLASSING

To create a new Alien module, inherit from this class and implement the following methods:

=head2 C<pkg_name( )>

B<Required>. Returns the name of the package as it appears in the C<xrepo> repository. May return a scalar or an array
reference / list of names when the module installs and exposes more than one library (for example, a binding to a
family of libraries such as SDL3). When multiple names are given, each is installed and recorded separately; the first
name is the C<primary> package used when no package name is passed to the delegation methods. This mirrors the
C<pkg_name> keyword of C<Alien::Build::Plugin::PkgConfig>.

Each entry may be a plain package name or a hashref that configures that package individually. The top-level hashref
keys are:

=over 4

=item B<< name => 'libsdl3' >>

B<Required>. The xrepo package name. No other key is valid without it.

=item B<< version => '3.4.12' >>

Optional. A version constraint for B<this package only>, overriding the C<version_constraint> constructor parameter.

=item B<< configs => { wayland => 1 } >>

Optional. A hashref of nested C<xrepo> recipe options. Each pair is serialized as C<--configs=key=value>, and the pairs
are merged over the C<configs> from L</"C<install_opts( )>"> or C<install()>, so a per-package option wins per key.
Boolean-ish values keep their truthiness when xrepo deserializes C<--configs=key=value> (C<1>/C<0> become true/false).

=item B<< kind => 'shared' | 'static' | 'binary' >>, L</"C<install_opts( )>"> flags

Optional. Any installer flag that L</"C<install_opts( )>"> accepts (C<plat>, C<arch>, C<mode>, C<toolchain>,
C<toolchain_host>, C<vs>, C<ndk>, C<sdk>, C<mingw>, C<jobs>, C<linkjobs>, C<force>, C<shallow>, C<build>, C<debugdir>,
C<includes>, C<yes>, C<confirm>) overrides the global option for this package. This is how one module builds a shared
library and a binary tool at once: each package carries its own C<kind>.

=back

Unknown top-level keys die at construction; the nested recipe options belong under C<configs>, and ambient options such
as C<local_repos> belong in L</"C<install_opts( )>">.

Precedence, highest first: the per-package entry, then C<install_opts()>/C<install()> options, then the xrepo defaults.
Recipe C<configs> merge per key with the per-package value winning.

=head2 C<package_names( )>

Returns the list of package names this module binds to (a single-element list for single-package subclasses).

=head2 C<alt( [$pkg] )>

Returns an object bound to the named package, mirroring C<Alien::Base'>s C<alt> accessor. Without an argument (or with
the primary package name) it returns C<$self>. With a different name it returns a delegate whose C<cflags>, C<libs>,
C<libpath>, C<bin_dir>, C<kind>, C<dynamic_libs>, C<dist_dir>, C<install_type>, C<version>, and related accessors all
refer to that package:

    my $ttf = Alien::SDL3->alt('libsdl3_ttf');
    my $cflags = $ttf->cflags;
    my $libs   = $ttf->libs;

This is the recommended way to access a non-primary package.

=head2 C<package_info( [$pkg] )> and enumerating packages

C<package_names> returns the names the module binds to, and each package's metadata lives in the
L<Alien::Xrepo::PackageInfo> object returned by C<package_info( $name )> (or by the C<alt( $name )> delegate). Drive an
C<install> first so every package is fetched and recorded, then iterate the names to build a report of what was
installed, where, and at what version:

    use Alien::SDL3;

    my $alien = Alien::SDL3->new;
    $alien->install;    # populate/refresh the per-package metadata

    for my $name ( $alien->package_names ) {
        my $alt = $alien->alt($name);
        my $info = $alt->package_info;
        next unless $info;               # package could not be located/installed

        printf "%-16s v%-9s %-8s\n", $name, $info->version, $info->kind;
        printf "  installdir : %s\n", $info->installdir // '(none)';
        printf "  libpath    : %s\n", $info->libpath   // '(none)';
        printf "  dynamic    : %s\n", join( '; ', @{ $info->libfiles // [] } ) || '(none)';
        printf "  includes   : %s\n", join( '; ', @{ $info->includedirs // [] } ) || '(none)';
        printf "  cflags     : %s\n", $alt->cflags;
        printf "  libs       : %s\n", $alt->libs;
    }

B<Note>: C<package_info> (and the delegation methods) return C<undef>/empty for a package that is not installed or
could not be resolved. You can tell a specific package is missing by checking that return value, e.g.
C<Alien::SDL3->alt('libsdl3_ttf')->libpath> is C<undef> (or C<package_info> itself is C<undef>) when C<libsdl3_ttf>
wasn't present. See the C<package_info> entry under L</METHODS>.

=head2 C<install_opts( )>

Optional. Returns a hash (or list) of options honored by the Builder (C<Build_PL> / C<Build>) when it installs the
package during the C<build> action. Pass these same options directly to C<install( %opts )> when installing at runtime.
These are the I<global> options applied to every package; a per-package hashref under L</"C<pkg_name( )>"> overrides
them for that package (and its C<configs> merge per key, with the per-package value winning). Supported keys:

=over 4

=item B<< kind => 'shared' | 'static' >>

Passed to xrepo as C<-k>. Ask for C<shared> explicitly when the goal is handing a dynamic library to an FFI binder; a
bare install without C<-k> resolves whatever xmake-repo happens to default to (often static archives).

=item B<< local_repos => [ $dir, ... ] >>

Registers each directory as a local xmake repository BEFORE any package is installed, so a patched copy of an upstream
recipe shadows the version in xmake-repo (local repositories are consulted first). Each directory must contain a
C<packages/> subtree laid out per xmake-repo conventions (C<packages/E<lt>nameE<gt>/E<lt>versionE<gt>/xmake.lua>). The
Builder registers each as a repo named C<alien-E<lt>basenameE<gt>> and removes this key from the opts handed to the
install itself.

A typical use: ship a small C<recipes/> tree containing patched copies of recipes your dependency stack builds badly
out of the box (for example this family carries a libsdl3_ttf recipe that forces freetype to build shared with zlib
disabled).

=item B<< yes => 1, confirm => 'no' >>

Auto-dismiss xmake/xrepo interactive prompts so captured installs never hang.

=item B<configs>

A hash reference of package-specific configuration flags.

=item B<< plat / arch / mode, toolchain, toolchain_host,
    vs / vs_toolset / vs_sdkver, ndk, sdk, mingw,
    jobs / linkjobs, force, shallow, build, includes >>

Passed through to xrepo as the equivalent flags (C<-p>, C<-a>, C<-m>, C<--toolchain=...>, C<--vs=...>, C<-j> /
C<--linkjobs=...>, C<--force>, C<--shallow>, C<--build>, C<--configs=...>, C<--includes=...>).

=back

=head1 METHODS

=head2 C<install( %opts )>

Explicitly triggers the installation of every package (optionally re-resolving). This is usually handled automatically
by the build system, but can be called manually at runtime if dynamic fetching is desired. Returns the primary
package's info.

=head2 C<upgrade( %opts )>

Updates the xrepo repositories and then calls C<install()>.

=head2 C<cflags( [$pkg] )>

Returns the compiler flags (typically C<-I> flags) required to use the library. Pass a package name to get the flags
for that package when the module binds multiple libraries, or use C<alt()>.

=head2 C<cflags_static( [$pkg] )>

Alias for C<cflags()>. Xrepo does not produce a distinct set of static compiler flags, so this is identical.

=head2 C<libs( [$pkg] )>

Returns the linker flags (typically C<-L> and C<-l> flags) required to use the library. Pass a package name to get the
flags for that package when the module binds multiple libraries.

=head2 C<libs_static( [$pkg] )>

Alias for C<libs()>, matching C<Alien::Base> naming.

=head2 C<split_flags( $flags, [$pkg] )>

Splits a C<cflags>/C<libs> string into a list of individual flags (using core C<Text::ParseWords>), mirroring
C<Alien::Base::split_flags>. The package argument is accepted for interface symmetry.

=head2 C<version( [$pkg] )>

Returns the version of the installed package.

=head2 C<libpath( [$pkg] )>

Returns the absolute path to the primary shared library.

=head2 C<ffi_lib( [$pkg] )>

An alias for C<libpath()>, provided for compatibility with C<FFI::Platypus>.

=head2 C<dynamic_libs( [$pkg] )>

Returns the absolute paths of the shared libraries / objects of the package. List context.

=head2 C<bin_dir( [$pkg] )>

Returns a list of directories containing executables.

=head2 C<kind( [$pkg] )>

Returns the type of installation: 'library' or 'binary'.

=head2 C<dist_dir( [$pkg] )>

Returns the directory where the package's files live (its xrepo install root).

=head2 C<install_type( [$pkg] )>

Returns C<'share'> once the package has been installed into the (local) xrepo root, and C<'system'> when nothing is
installed yet. This mirrors the C<install_type> contract of C<Alien::Base>.

=head2 C<find_header( $filename, [$pkg] )>

Searches the package's include directories for the specified header and returns its absolute path.

=head2 C<package_info( [$pkg] )>

Returns the raw L<Alien::Xrepo::PackageInfo> object containing all metadata. C<libfiles> from xrepo map to
C<dynamic_libs>, and C<installdir> maps to C<dist_dir>.

=head2 C<package_defs( )>

Returns a hashref of package name to normalized per-package definition, for the entries declared as a hashref under
L</"C<pkg_name( )>">. Plain package names carry no entry. Both C<Alien::Xrepo::Base::install()> and the Builder consult
this (via the C<_version_for_pkg> / C<_opts_for_pkg> helpers) so each package installs with its own version, flags, and
recipe configs.

=head1 BUILDER METHODS

These methods are intended for use in C<Build.PL> and the generated C<Build> script.

=head2 C<Build_PL( $alien_class )>

Creates the C<Build> script and stores build parameters. C<$alien_class> should be the name of your subclass.

=head2 C<Build( [$alien_class] )>

The entry point for the C<Build> script. Orchestrates the C<build>, C<test>, C<install>, and C<clean> actions.

=head1 TIPS AND TRICKS

=over 4

=item Keep the default package store

The Builder deliberately installs into xrepo's global store and shallow-copies the finished artifacts into the module's
share dir. Do NOT redirect the store via C<installdir> unless you have a reason: a redirected store makes xmake re-exec
with C<system=false> (no apt/Homebrew/MSYS system packages) and rebuilds the whole dependency tree from source, which
is what breaks shared links (e.g. libsdl3_ttf) on Linux/macOS. The default store resolves dependencies the same way a
bare C<xrepo install> does.

=item Ask for shared when the FFI binder needs it

An FFI binder such as L<Affix|https://metacpan.org/pod/Affix> loads dynamic libraries, so pass C<< kind => 'shared' >>
and feed C<dynamic_libs>/C<ffi_lib> to it. Without C<-k> you may receive a static archive and the bind will fail at
load time.

=item Mix shared libraries and binary tools per package

C<install_opts> holds one set of options for the whole family, so you cannot express "libsdl3 as a shared library,
ninja as a binary" with it alone. Give each package a hashref under L</"C<pkg_name( )>"> instead: the library entry
carries C<< kind => 'shared' >> (plus any recipe C<configs>) and the tool entry C<< kind => 'binary' >>. Write the FFI
binder against the primary library's C<dynamic_libs>/C<ffi_lib>, and run the tool through the package's C<bin_dir>.

=item Ship patched recipes, wait for no one

If a dependency in the resolved tree mis-builds on some platform (CMake C<find_package> failures for deps xmake passes
no variables for are common -- e.g. freetype vs. zlib), ship a corrected recipe in your C<recipes/> tree with the exact
C<package(...)> body adjusted (freetype: build shared, I<and> disable zlib via C<-DFT_DISABLE_ZLIB=ON>) and register
the tree via C<local_repos>. Local repositories win over xmake-repo.

=item Windows: the scratch-project pitfall

xrepo's private scratch project lives at C<%TEMP%\.xmake\E<lt>yymmddE<gt>\xrepo\working\> and is created on demand by
C<xmake create -P .>. On GitHub Actions that create can abort while the template is rewritten, leaving a I<read-only>
xmake.lua with unexpanded tokens (C<${TARGET_NAME}>, a bare C<${FAQ}>), so every later xrepo action dies parsing
C<.\xmake.lua: unexpected symbol near '$'>. The wrapper pre-sows and repairs that directory on MSWin32 so a subclass
needs to do nothing -- but if you ever see exactly that error, look for a stray, read-only
C<%TEMP%\.xmake\...\xrepo\working\xmake.lua> or a tool that wrote to the real TEMP ahead of your build.

=item Version constraints

Pass a constraint as the second argument to L</"C<install( %opts )>"> so a bare C<./Build> resolves the same versions
you developed against (C<< $alien->install( 'libsdl3', '3.4.x' ) >>). The C<version_constraint> constructor parameter
does the same for every package.

=item Disable the wrapper's own test suite in CI

The wrapper's test suite performs network package installs (pcre2) and can flake on slow runners. Install it Notest
(C<< cpanm -n https://github.com/sanko/Alien-Xmake.git >>) and gate on your own distribution's tests.

=item Debugging xrepo installs

Set C<< verbose => 1 >> on the constructor (or C<XMAKE_THEME=plain> to kill ANSI) and watch the C<[XREPO] cmd (cwd:
...)> line the wrapper echoes; the cwd it reports reveals where xrepo believes its project root is. C<< ./Build
clean_cache >> (also honored via C<ALIEN_XREPO_CACHE>) clears the shared package store when a poison gets in.

=back
